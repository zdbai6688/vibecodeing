## 一、现状分析

### 1.1 麒麟速记（Kylin Note）概要

| 属性 | 信息 |
|------|------|
| 产品名称 | 麒麟速记（Kylin Note） |
| 包名 | cn.kylin.kylin-note |
| 版本 | 2.0.0.0-0k0.3 |
| 开发语言 | C++（Qt5/QML） |
| 模块数 | 8个共享库（.so） |
| 定位 | 笔记+待办+周报+会议助手 四合一办公工具 |

**核心功能矩阵：**

| 功能模块 | 子功能 | 优先级 |
|---------|--------|-------|
| 快速录入 | Alt+Space全局唤起的快速输入窗口，支持文字/语音/标签 | P0 |
| 笔记管理 | 富文本编辑（字体/颜色/图片）、标签分类、搜索/排序/回收站 | P0 |
| 待办管理 | 截止日期、优先级、完成状态、已完成管理 | P0 |
| 智能周报 | 自然周视图、完成统计、AI辅助生成 | P1 |
| 会议助手 | 录音控制、实时转写、发言人识别、AI摘要、时间戳 | P0 |
| AI能力 | ASR转写、大模型摘要/待办提取、AI周报 | P0 |

**麒麟速记的亮点：**
- 全局快捷键（Alt+Space）快速录入，极低使用门槛
- 会议录音+实时转写+AI摘要一站式解决会议记录痛点
- 笔记/待办/周报数据闭环，信息管理链路完整
- 桌面原生体验，深度集成操作系统

**麒麟速记的不足：**
- 依赖麒麟平台专有SDK（libkysdk-coreai-speech, libkyai-assistant等），无法跨平台
- 语音识别依赖云端（百度/讯飞），离线能力弱（PocketSphinx精度低）
- 富文本编辑器自研，功能有限
- 无AI助手独立对话能力

### 2.3 竞品关键洞察

**快速捕捉能力（UOS速记差异化核心）：**
- Drafts（Mac）的全局快捷键+Action扩展是标杆
- Apple Notes 系统级集成（选中文字→新建笔记）
- **麒麟速记的Alt+Space是Linux桌面独一无二的快速入口**

**AI能力趋势：**
- Notion AI、Otter.ai、飞书妙记 都在做AI原生
- 会议自动摘要、待办提取、写作辅助是标配
- **UOS速记需要AI能力但不需要自研大模型**，对接API即可

**离线能力：**
- Obsidian、Apple Notes、OneNote 都支持完整离线
- 语音转写是唯一需要联网的场景
- **Whisper.cpp 本地ASR 是关键差异化武器**

**商业模式：**
- Notion/Otter 采用 Freemium 模式
- 讯飞听见按分钟计费
- **UOS速记作为系统预装应免费，AI能力可按时长或次数计费**

## 三、UOS 速记产品定位

### 3.1 产品定位

> **"UOS速记"——统信UOS原生的办公信息中枢**
> 轻量级笔记 + 待办管理 + AI会议助手 三合一

**一句话概括：** 比 deepin-voice-note 更强大，比 麒麟速记 更开放，对标 Drafts 的快速捕捉 + Notion 的 AI 能力 + Apple Notes 的原生体验。

### 3.2 目标用户

| 用户画像 | 使用场景 | 核心需求 |
|---------|---------|---------|
| **政企办公人员** | 会议记录、工作备忘、待办跟踪 | 会议转写、AI纪要、信息安全 |
| **开发者/技术用户** | 快速记录代码灵感、技术笔记 | Markdown支持、全局快捷键 |
| **普通UOS用户** | 日常记账、灵感记录、学习笔记 | 快速启动、语音输入、简单易用 |
| **听障人士** | 会议实时字幕、语音转文字 | 实时字幕、高精度转写 |

### 3.3 差异化策略

```
                    ┌──────────────────────┐
                    │    UOS速记差异化        │
                    ├──────────────────────┤
                    │ 1. 全局快捷键捕捉       │
                    │ 2. Whisper本地离线转写   │
                    │ 3. Markdown原生笔记     │
                    │ 4. 深度UOS DTK原生体验  │
                    │ 5. 玲珑包发布+应用商店   │
                    │ 6. 数据100%本地（隐私）  │
                    └──────────────────────┘
```

### 3.4 技术选型方案对比

| 方案 | 技术栈 | 优势 | 劣势 | 推荐度 |
|------|-------|------|------|-------|
| **A. Qt6 + DTK6（推荐）** | C++20, Qt6, DTK6, CMake | 原生性能、UOS深度集成、可复用现有代码 | 开发周期较长 | ⭐⭐⭐⭐⭐ |
| **B. Electron + Vue/React** | TypeScript, Electron, Node.js | 开发效率高、跨平台、Web生态 | 性能一般、包体积大、非原生体验 | ⭐⭐⭐ |
| **C. Rust + GTK4** | Rust, GTK4, libadwaita | 高性能、内存安全 | 生态不成熟、UOS集成弱 | ⭐⭐ |
| **D. Flutter** | Dart, Flutter Linux | 跨平台、热重载、UI表现力强 | 包体积大、Linux支持仍在完善 | ⭐⭐⭐ |

**推荐方案 A：基于 Qt6 + DTK6 复刻 deepin-voice-note 并增强**

理由：
1. UOS 系统已预装 DTK6 运行时，包体积最小
2. 可复用 deepin-voice-note 现有代码（录音、播放、富文本编辑）
3. DTK6 提供原生 UOS 外观和交互（主题、标题栏、动画）
4. Qt6 的 QtMultimedia、QtWebEngine 可直接满足音视频和富文本需求
5. 玲珑包支持 Qt6 应用

### 8.2 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 全局快捷键在Wayland下受限 | P1功能阻塞 | 初期主推X11，Wayland使用portal D-Bus方案 |
| ASR云服务API费用 | 运营成本 | Whisper.cpp离线兜底，免费额度扣费 |
| 玲珑包Qt6运行时兼容性 | 发布延迟 | 提前搭建玲珑构建环境测试 |
| AI大模型API不稳定 | 用户体验 | 设计重试+降级机制，缓存常见结果 |
| 项目人手不足 | 进度延迟 | 优先P1功能，确保MVP按时发布 |

### 8.3 从deepin-voice-note继承的优势

deepin-voice-note 已有代码可直接复用的部分：

| 模块 | 文件 | 复用方式 |
|------|------|---------|
| 录音引擎 | GStreamer录音相关代码 | 直接继承 |
| 音频处理 | 裁剪、格式转换 | 直接继承 |
| DBus通信 | dbuslogin1manager | 直接继承 |
| 音频播放 | 波形显示、播放控件 | 直接继承 |
| 玲珑包配置 | linglong.yaml | 修改后复用 |
| 翻译框架 | translations/ | 直接继承 |

## 九、总结

UOS速记的定位不是简单地"复刻麒麟速记"，而是：

1. **站在巨人肩膀上**：继承 deepin-voice-note 的成熟录音能力
2. **对标麒麟速记**：补齐笔记、待办、全局快捷键、AI能力
3. **超越竞品**：Whisper本地离线转写是Windows/Mac都没有的差异化优势
4. **真正可发布**：玲珑包 + 应用商店 + 用户手册

**核心建议：**
- 技术选型：Qt6 + DTK6（UOS原生最优解）
- 第一阶段（4周）先做MVP，实现笔记+待办+全局快捷键
- 第二阶段（3周）加上AI能力，达到麒麟速记同等水平
- 第三阶段（4周）Whisper离线转写，实现超越
- 第四阶段（2周）打包发布，正式上线
