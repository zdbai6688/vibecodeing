## 2. API Key 存储安全

### 现状
- API Key 通过 `QSettings` 存储（默认 `~/.config/UOS速记/settings.conf`）
- 输入框使用 `QLineEdit::Password` 模式（输入时掩码显示）
- QSettings 默认以 INI 格式明文存储

### 风险
| 风险项 | 等级 | 说明 |
|--------|------|------|
| API Key 明文存储 | **中** | QSettings 未加密，其他进程可读取 |

### 改进建议
- **短期**：QSettings 文件设置 600 权限（仅所有者可读写）
- **中期**：使用系统密钥环（libsecret/libgnome-keyring）存储 API Key
- **长期**：支持 OAuth 令牌交换

### 审计结果
**有条件通过** — 短期风险可接受（API Key 仅本地使用，非共享环境）。

## 3. 路径遍历防护

### 审查文件
- `src/storage/database.cpp` — 数据库路径固定，无用户输入
- `src/audio/audiorecorder.cpp` — 录音文件路径固定，无用户输入
- `src/services/migration.cpp` — 外部数据库路径固定

### 审计结果
**通过** — 所有文件操作使用固定路径或 Qt 标准路径，无用户输入拼接。

### 新增建议
- 所有文件操作使用 `QFileInfo` 验证路径合法性
- 导出功能中对用户输入的文件名做过滤（移除 `../` 等）

## 4. 输入验证

### 审查项目
| 输入点 | 验证方式 | 状态 |
|--------|---------|------|
| 笔记标题 | QLineEdit 最大长度限制 | ✅ 内置 |
| 笔记内容 | QTextEdit 无限制 | ⚠️ 建议添加 MAX_CONTENT_LENGTH 检查 |
| 搜索关键词 | SQL 参数化查询 | ✅ 防注入 |
| API Key 输入 | 无验证 | ⚠️ 建议添加格式校验 |
| 录音文件路径 | 固定路径 | ✅ 安全 |

### 审计结果
**基本通过** — SQL 注入已通过参数化查询防护。建议添加内容长度和 API Key 格式校验。

## 5. SQL 注入防护

### 审查结果
- 所有 SQL 查询使用参数化查询（`query.bindValue`）
- 无字符串拼接 SQL
- 数据库连接使用 WAL 模式，synchronous=NORMAL

### 审计结果
**通过** — 无 SQL 注入风险。

## 6. 文件权限
